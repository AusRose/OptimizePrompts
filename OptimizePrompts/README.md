# 优化提示词（Optimize Prompts）

DeepSeek Harness（DSH）的提示词优化插件。在输入框左下角的权限预设选择器（如「工作区内修改」）旁点击「优化」，当前草稿会被 DSH 已配置的模型改写成更清晰的提示词；需要时还会把经校验的文件与技能引用追加到末尾。

**优化结果只替换输入框内容，不会自动发送。安装或更新插件后请重新启动 DeepSeek Harness。**

## 功能

- **一键改写**：保留原意、语言和具体细节，整理表达，补充真正属于该任务的信息；不会替用户答题，也不会强加模板。
- **识图**：输入框里附带的图片会一起交给改写模型，让它按图片内容整理提示词。图片不会写进提示词，仍随你发送的消息带出。
- **模型可选**：复用 DSH 的模型目录与凭证。默认优先 `deepseek-account / deepseek-flash`（支持图片）；部署没有该模型时回退到 DSH 默认模型。
- **引用文件**：模型提名路径后，通过当前会话工作区的文件索引校验，再追加 `@路径`。
- **引用技能**：通过当前会话可见的技能目录校验，再追加 `/技能名`；提供关闭、严格、均衡和宽松四档。
- **保留草稿**：请求失败时保留原稿；请求期间编辑、发送或切换会话后，迟到的结果不会覆盖当前输入。
- **独立请求**：不改变聊天的模型与思考强度，也不写入会话历史。

## 安装

### 从本地目录安装

需要 Node.js 24 或更新版本，以及可用的 `dsh` 命令。构建不需要额外 npm 依赖。

```powershell
cd C:\path\to\OptimizePrompts
node build.mjs
```

对可由 CLI 管理的 profile，使用本目录的绝对路径安装（profile 名和路径请换成自己的）：

```powershell
dsh plugin --profile my-profile add "link:C:/path/to/OptimizePrompts"
```

安装或更新后重启对应的 DSH 实例。桌面 profile 由应用管理：打开「插件 → 添加插件」，在「包名或地址」中输入本地目录路径即可（该界面同时支持 npm 包名和 Git 仓库地址）。不要把 CLI profile 当成桌面 profile。

> **不要把插件源码复制进 profile 的 `node_modules`。**
> `node_modules` 是 pnpm 管理的生成目录，不是安装位置。不在 `package.json` 依赖树里的目录会在下一次安装时被移动到 `node_modules/.ignored`，这也是“目录明明在、插件列表却没有”的常见原因。正确做法是让项目留在任意稳定目录，再用「添加插件」或 `dsh plugin add "link:…"` 建立链接。

### 确认已启用

1. 重启 DSH。
2. 打开「插件」列表，确认「优化提示词」已启用。
3. 确认 DSH 至少配置了一个可用模型，然后打开「设置 → 优化提示词」。

## 使用

1. 选择一个工作区，进入会话。
2. 在输入框写下草稿。输入框有文字时，左下角「工作区内修改」选择器右侧会出现星形「优化」按钮。
3. 需要让改写参考图片时，把图片附在草稿上（一次最多 4 张）。
4. 点击「优化」，等待按钮从「优化中」恢复。
5. 检查替换后的草稿及末尾的文件、技能引用，必要时继续编辑，再点击发送。

按钮只在草稿有文字时出现；发送过程中（提交/裁决阶段）按钮会被禁用，避免覆盖正在发送的内容。

## 设置说明

| 设置 | 行为 |
| --- | --- |
| 模型 | 默认选中 DeepSeek Account 的 DeepSeek Flash（`deepseek-flash`）；下拉只列当前可路由的真实模型 |
| 思考强度 | 使用所选模型提供的等级；「默认」交给模型适配器处理 |
| 引用文件 | 默认开启；关闭后不追加新的文件引用 |
| 引用技能 | 默认均衡；可改为关闭、严格或宽松 |
| 让优化参考图片 | 默认开启；关闭后改写只看到文字，附图不会发给优化模型 |
| 优化指令 | 决定重写风格，可编辑；「恢复默认」恢复内置指令 |

设置修改后自动保存，页面会显示保存状态；保存失败会显示错误。切换优化模型会清空原有的思考强度选择，避免沿用不适合新模型的等级。

### 模型优先级

改写实际使用的模型按以下顺序确定，设置页显示的也是同一个结果：

1. 设置里保存且当前目录仍存在的 provider / model；
2. `deepseek-account / deepseek-flash`（部署提供时）；
3. DSH 的默认模型。

优化调用不会改变聊天会话的模型或思考强度。

## 图片

输入框里附带的图片会随改写请求一起发送给优化模型，让它在整理提示词时看得见图片内容——例如「按这张截图的布局改」。这里有三个边界：

- **图片不会进入提示词**。改写结果只替换文字，图片仍附在草稿上，随你发送的消息一起带出。
- **只有图片会被转发**。文件附件不参与改写：它本来就随发送带出，插件没必要再复制一份。
- **模型必须支持视觉**。插件先查所选模型的 `inputModalities`；模型只接受文字时，图片会被跳过，按钮提示会说明原因。部署没有附件服务、图片超限或格式不被接受时同样只跳过图片，文字改写照常完成。

图片的格式、张数、单张与总量上限沿用 DSH 自身的附件策略；插件另外限制一次最多 4 张、单张 base64 不超过 8 MiB。浏览器会在发请求前截断到 4 张，Host 还会再校验一次。

## 自动引用

开启自动引用后，模型在改写时提名文件与技能。插件不会直接采信模型输出：文件路径先经当前会话工作区的文件索引校验，技能名先经当前会话可见的技能目录校验，只有确认存在的项目才会追加到提示词末尾。

示例：

```text
Files this task needs:
@docs/project-experience.md
@docs/target-role.md

Skills this task may need:
/make-resume
/great-resume
```

`@路径` 为文件或目录引用，发送后是否读取由 DSH 的 Agent 决定；`/技能名` 是 DSH 的技能调用手势，发送后由 DSH 处理。技能必须在当前会话目录中可见，并且同时允许模型调用和用户调用。

| 技能档位 | 提名规则 |
| --- | --- |
| 关闭 | 不追加技能引用 |
| 严格 | 请求明确需要该能力或任务离不开它时才提名，最多 2 个 |
| 均衡 | 提名确实有帮助的技能，最多 3 个 |
| 宽松 | 提名所有可能有帮助的技能，不限数量 |

文件提名最多 5 个。某一类没有有效提名时，插件可能列出真实候选再补充一次提名请求，因此开启引用可能增加调用次数和等待时间。已有引用会合并去重；含空格的路径按 DSH 的引用语法加引号；歧义路径不会猜选。

最近一次处理状态会显示在按钮提示和设置页：引用已确认、未发现相关引用、处理未完成、原稿已保留或自动引用已关闭。

## 数据与限制

- 设置保存在 `$DSH_HOME/optimize-prompts.json`；未指定 `DSH_HOME` 时使用用户目录下的 `.dsh/optimize-prompts.json`。
- 单次草稿上限 60,000 字符；模型输出上限 4,096 tokens；单次模型请求超时 120 秒。
- 单次请求体上限 40 MiB。超过时返回可读的 413 错误，而不是断开连接。
- 引用阶段另有 15 秒总预算；文件提名最多 5 个，严格/均衡档技能提名最多 3 个，宽松档不设数量上限。

## 常见问题

**按钮没有出现**

先在输入框输入文字，并确认已选择工作区、插件已启用。安装或更新后需要重启 DSH；浏览器刷新不能代替 Host 插件重新加载。

**插件目录在，但插件列表里没有**

确认它不是被复制进了 profile 的 `node_modules`。检查 profile 的 `package.json` 是否有 `dsh-optimize-prompts` 依赖，以及 `dsh.profile.bundles` 是否包含它；两者都由「添加插件」或 `dsh plugin add` 写入。只把文件夹放进 `node_modules` 不会安装插件，pnpm 下一次操作还会把它移走。

**没有模型，或优化失败**

先确认 DSH 本身能调用所选模型，再检查插件设置中的模型。错误会显示在按钮提示和设置页；原草稿会保留。

**附带的图片没有影响结果**

依次确认：设置里的「让优化参考图片」是否开启；所选模型的 `inputModalities` 是否包含 `image`；图片是否超过 DSH 的附件限额或插件的 4 张上限。以上任一情况都会只跳过图片、保留文字改写，按钮提示里会写明原因。

**没有追加文件或技能**

确认对应引用开关已开启、会话已关联正确工作区，以及文件索引和技能目录可用。没有相关引用也可能是正常结果；开启引用不保证每次都能找到合适的项目。技能名还必须同时允许模型调用和用户调用。

**为什么优化后草稿没有变化？**

如果请求期间编辑了草稿、发送了消息或切换了会话，插件会丢弃返回结果。检测到原始路径或 `@引用` 丢失时，也会保留原稿。

**等待时间较长**

耗时取决于模型、草稿长度、图片数量，以及引用阶段是否触发候选补充提名；不提供固定完成时间。单次模型请求上限为 120 秒，引用处理另有 15 秒预算。

**长草稿失败**

草稿上限是 60,000 字符，但输出上限是 4,096 tokens；很长的草稿可能先触发输出长度限制。把任务拆成几段通常更稳。

**启用时提示 `pending (waiting for service: optional)`**

更新到当前构建并重启 DSH。本实现按需获取服务，不使用会导致该问题的 `inject: { optional: [...] }` 写法。

## 开发

编辑 `src/` 后重新构建，不要直接修改 `lib/`。

```powershell
node build.mjs   # 生成 lib/index.js 与 lib/client.js
```

| 路径 | 用途 |
| --- | --- |
| `src/client.js` | 优化按钮、图片转发、引用状态、草稿保护、设置页和中英文文案 |
| `src/host.js` | 设置存储、模型请求、图片准入、文件/技能引用校验和 HTTP 接口 |
| `src/shared.js` | 默认指令、路由、状态和各项限制 |
| `build.mjs` | 把 shared 内联进两半，并把客户端包成 DSH 的模块工厂 |
| `cordis.patch.yml` | 插件装配配置 |
| `locale/` | DSH 插件列表中的显示名称与描述 |

更完整的设计说明、接口契约和调试方法见 [PROJECT.md](PROJECT.md)。

## 卸载

从 DSH 的插件列表禁用或移除「优化提示词」，然后重启。插件只新增 `conversation.input.left` 与 `settings.section` 两个入口，移除后不会留下被覆盖的界面。设置文件可以手动删除。
